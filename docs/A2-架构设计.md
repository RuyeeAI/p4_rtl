## 1. 前置实验一：多通道 / 多表的 II（P0 遗留）

### 1.1 为什么要做

P0 遗留事项原文：「多通道 / 多表在同一 proc 内的 II 未验证 —— A3 首个检查点就该扫。」
而 A2 的架构选择直接依赖它：P4 的 control 可能有 N 张 runtime table，
每张表要一对 key/rsp 通道。

- 若多对通道仍能 II=1 → **整个 control 可以放进一个 proc**（结构简单得多）
- 若不能 → 必须限制「每 proc 一张表」，编排方案完全不同

### 1.2 实验设计

`scripts/gen_multichan_probe.py N` 生成「N 张表争用同一 proc」的探针：

```
IDLE(发key1) → WAIT1(收rsp1) → MID1(发key2) → WAIT2(收rsp2) → ... → DISPATCH(发result) → IDLE
   相位总数 2N+1；通道数 2N+1（N 个 key_out + N 个 rsp_in + 1 个 result_out）
```

与 M0/P0 保持一致的做法（**只把"通道对数"当唯一变量**）：
- 所有通道操作都直连 `state_read(tok__1)`、**互不串链**；
- 各操作的 predicate（FSM 相位）互斥；
- 末尾 `after_all` 汇聚；
- 第 i 张表（i≥2）的 key 取自上张表的 response —— 复现真实表级串联依赖。

### 1.3 结果

| 表数 N | 通道数 | 最小 II | stages 1..4 |
|---|---|---|---|
| 2 | 5 | **1** | 全 ✓ |
| 3 | 7 | **1** | 全 ✓ |
| 4 | 9 | **1** | 全 ✓ |
| 6 | 13 | **1** | 全 ✓ |
| 8 | 17 | **1** | 全 ✓ |

**结论：通道数量（至少到 17 个）不是 II 的瓶颈。** 整个 control 可以放进一个 proc。

### 1.4 踩坑记录（值得单独记）

第一次用生成器跑 N=3/4 时全部失败，报 `Invalid parameter keyword argument \`init\``。
一度以为是 XLS 对通道数量的限制，**实际是生成器的低级 bug**：

`",\n".join(state_params)` 生成的**最后一个 state 形参没有逗号**，而它后面紧跟
`init={...}`，于是缺了分隔符。手写的 2 表样本（有逗号）反而通过 ——
正是这个对比把问题指向了生成器而非工具链。

> **教训**：用生成器做实验时，先用一个**手写样本**跑通同一结构，
> 再让生成器对齐 —— 否则无法区分「工具的 bug」与「工具链的限制」。

## 2. 前置实验二：proc 内 invoke（复用 action 生成器的前提）

### 2.1 为什么要做

现有 `IrText.dump` 已能把一个 action 的 Dag 发射成 XLS `fn`（A0/A1 验证 25/25 通过）。
A2 要做的是 control 的**编排**。如果 proc 能 invoke 这些 fn，
就不必把 action 的几百个节点内联进 proc。

### 2.2 结果：✅ 可用

`testcases/a2/probe_proc_invoke.ir` → `out/a2/probe_proc_invoke.v`：

```verilog
module invoke_probe(
  input wire clk, rst, input wire [31:0] data_in, input wire data_in_vld,
  input wire data_out_rdy,
  output wire [31:0] data_out, output wire data_out_vld);
  wire [31:0] one;
  wire [31:0] res;
  assign one = 32'h0000_0001;
  assign res = data_in + one;      // ← 被 invoke 的 fn 被**内联展开**（无独立子模块）
  assign data_out = res;
  assign data_out_vld = data_in_vld;
endmodule
```

### 2.3 两条必须记住的规则

**规则 1 —— invoke 的返回类型取决于被调函数：**

| 被调函数形态 | invoke 写法 |
|---|---|
| 纯数据函数（无形参 token） | `<name>: <retT> = invoke(args..., to_apply=f, id=N)` |
| 接受 token 形参的函数 | `<name>: (token, <retT>) = invoke(tok, args..., to_apply=f, id=N)` |

踩过的坑：对纯数据函数写成 `(token, bits[32]) = invoke(t1, got, to_apply=add_one)`，报

```
Declared type (token, bits[32]) does not match expected type bits[32]
```

官方两处带 token 的 invoke 样本（`invoke.22` / `invoke.44`），被调函数名都带
`__itok__` 前缀，即 implicit-token 函数 —— 与规则一致。
官方 `ParseInvoke.ir` 是纯数据版：`ret invoke.3: bits[32] = invoke(x, literal.2, to_apply=bar)`。

**规则 2 —— 节点 id 必须 package 级全局唯一：**

```
ID 1 is not unique; source locations of nodes with same id: [], []
```

`fn add_one` 用了 id 1..2，proc 里再从 1 开始就冲突。
**这对生成器设计有直接影响：需要一个跨 fn/proc 的全局 id 分配器**（见 §3.5）。

## 3. 架构定案

### 3.1 proc 划分：一个 P4 程序 → 一个 proc

```
.P4 源码
   ↓ Parser（现有前端）
P4Program (AST)
   ↓ XlsBackend
XLS IR 文本：
   package <pkg>
   fn <action>...        ← 复用 IrText.dump（已有能力）
   #[initiation_interval(1)]
   top proc <pipeline>   ← A2 新增
   { FSM: parser states → control phases；通道 = 表接口 + 包输入输出 }
```

**为什么是单 proc（而不是 parser/control 各一个 proc）：**
- 跨 proc 互连需要 package 级 `chan` 声明 + 绑定（**尚未验证**）；
- 单 proc 是已验证形态（M0 的三通道、A2-0 的 17 通道）；
- 第一版优先「跑通最小闭环」。

**代价与后续**：proc 会比较大。将来若需要拆分，
`A2-0` 的结论（多通道不是瓶颈）说明通道数不是障碍，
但要先补验「跨 proc 的 chan 绑定」这一项。

### 3.2 PHV（包头向量）表示：扁平化成 `bits[K]`

- 编译期确定每个 header 字段的 bit offset 与宽度 → `HeaderLayout`
- 每个 header 有一个 **valid 位**（parser 是否解析到）
- parser 的 `extract` = 从输入包数据里 `bit_slice` 出该 header 的位段
- 对定长 header（现有 demos 都是），offset 是编译期常量 ⇒ 直接 `bit_slice`

### 3.3 FSM 相位设计

```
phase 0        : parser 起始（start）
phase 1..P     : parser 各 state（每 state 一拍）
phase P+1      : control 起始
每张 runtime 表: 2 拍（发 key / 收 rsp）+ 1 拍 action 执行
末尾           : 输出（deparse / PHV 出）
```

各通道操作的 predicate 由相位派生、**互斥**（P0 的硬性要求）。

### 3.4 action 的执行方式：**内联进 proc**（原定 invoke `fn`，A2-4 实测后改）

原方案是 `action 的 Dag → fn`，proc 里 `invoke` 它（A2-0 §2 已实测 invoke 可用）。
A2-4 落地时改成**把 Dag 直接内联发射进 proc**（`XlsBackend.emitDagInto`），理由：

| | invoke `fn` | 内联（选定） |
|---|---|---|
| 复用收益 | 无 —— 实测 XLS **对 invoke 也是内联展开**（§2.2 生成的 RTL 里被调函数无独立子模块） | 同左 |
| fn 形参/返回值如何对接 proc 的 state | **未验证**（fn 参数是「路径即参数」，与 proc 的 state 读节点之间需要一层适配） | 不需要：`Ir.InputRef` 直接落到 state 读节点 |
| 额外语法要求 | 须满足 §4-A2 的 invoke 返回类型规则 | 无 |

内联后**依然复用既有实现**：`action` 的 body 仍走 Chisel 线的
`IrBuilder.ExprLowering`（宽度推断 / 位宽 fit / 运算符映射一份实现），
再经 `Passes.runAll` 优化，最后按 `Ir.Node` 逐节点映射到 `XlsProc.Builder` ——
这张映射表与 `IrText.dump` 是同一张（`Const→literal`、`Zext→zero_ext`、
`Trunc/Slice→bit_slice`、`Cat→concat`、`Mux→sel(cases=[假,真])`、`Bin→add/…`）。

> 若将来一个 action 需要被多处复用、或 proc 大到该拆分，再把这条路径换成
> `fn` + invoke 即可 —— 那时要先补验「fn 形参与 proc state 的对接」。

**第一版不支持 action 里的 extern 写**（Register/Counter）—— 见 §5/§6。

### 3.5 control 的 proc 布局（A2-4 落地）

```
相位 0        : 收 PHV（phv_in）→ 拆成各字段（bit_slice）写回 state
相位 1..S     : apply 体每条语句一拍（action / 表 / 赋值）
相位 S+1      : 发 PHV（phv_out）← 各字段 concat 回去
相位 S+1 之后 : 回到 0，重新收包
```

- **state 用字段级**（`<param>_<member>[_<field>]` 一个 state），而不是 header 级：
  control 的 action 是局部修改（`meta.cls = c`），字段级让「改哪个就更新哪个」最直接。
- **PHV 布局** = control 参数展平序（params 按声明序 → struct 成员按声明序 →
  header 字段按声明序），先声明者在**高位** —— 与 `concat` 的左=MSB 一致。
- **const 表编译期内联**：逐表项算 `hit_i`（逐 key 元素比较后 `and`，与整体
  `concat` 后比较等价），每条表项的输出作为候选值，再按**声明序优先**倒序嵌套
  `sel` 选出；`default` 表项的输出作基线（优先级最低）。
- **每条语句一个相位**：相位互斥 ⇒ 各字段的 next 值 = 逐相位 `sel` 链，
  天然实现「后写的覆盖先写的」。

### 3.6 id 分配：全局单调计数器

由 §2.3 规则 2，`XlsBackend` 内部维护**一个** id 计数器，
所有 `fn` 与 `proc` 的节点共用，**不重置**。

## 4. A2 版技术约束清单

在 M0 的 6 条（K1–K6）与 P0 的 2 条（不串链、predicate 互斥）之外，A2 新增：

| # | 约束 | 来源 |
|---|---|---|
| A1 | **节点 id 在整个 package 内全局唯一** | §2.3 规则 2，实测报错 |
| A2 | invoke 纯数据 fn 时**不加 token**；带 token 形参的 fn 才返回 `(token, ...)` | §2.3 规则 1，实测报错 |
| A3 | 多通道不构成 II 瓶颈，但**前提仍是「通道操作不串链 + predicate 互斥」** | §1（本实验只验证了这个前提成立时的情形） |
| A4 | 每张 runtime 表一对 `key_out`/`rsp_in`，走 `valid_data`（无背压） | 用户 2026-09-16 决策 |

## 6. 未决项：extern 状态的存放

demo5/demo9 有 `Register(bit<16>, 8)` / `Counter(bit<32>, 8)`，
需要 8 个元素的存储。两条路：

| 方案 | 说明 | 风险 |
|---|---|---|
| **(a) proc 的 state 直接用数组** `bits[16][8]` | 最自然（M0 里 `array_index` 已用于数组参数） | **proc 的 state 是否允许数组类型尚未验证** |
| (b) 展开成 8 个独立 state + `sel` 读写 | 一定可行 | size 大时爆炸；`sel` 的 cases 线性增长 |

**另有一条更符合项目裁剪的路线**：方案 v2 里 counter/meter/register 属 M3
（"外部状态"），本期 A2 本就不做 —— 即 **A2 第一版不支持 extern，遇到就报明确的诊断**。

> 但要注意：extern 在 demo5/demo9 里存在，A2 若跳过它们，
> 端到端语料就只剩 demo1/2/3/7/8/10/11。建议按 §5 的顺序推进，
> 到 A2-5 时再决定走 (a) 还是 (b)。

### 7.1 踩坑：bash 3.2 会把紧跟 `$VAR` 的全角标点算进变量名

macOS 自带 `bash 3.2.57`。脚本里写

```bash
echo "样本：$STEM（top=$TOP）"     # ← U+FF08 左圆括号是**全角**
```

会报 `STEM…: unbound variable` —— bash 3.2 在 multibyte locale 下把全角标点
的字节也当成了标识符字符。**中文注释密集的脚本很容易踩**（错误信息还乱码，
看不出是标点问题）。

修法：变量一律写 `${VAR}` 显式界定。`scripts/a2_verify.sh` 里已标注这一点。
