### 写之前先摸清的语法子集边界（**下次写 P4 必看**）

| 约束 | 出处 | 影响 |
|---|---|---|
| **无 `if/else`** | `Ast.Stmt` 无条件语句 | 下游表无法被上游跳过 ⇒ 用「元数据参与表 key」门控 |
| **无 apply 内局部变量** | `XlsBackend:667` / `ChiselBackend:692` 直接抛错 | 临时值只能用表达式复用 |
| **表 key 只能是字段路径**（不能写 `hdr.x[31:8]`） | `XlsBackend:327/616` 模式匹配只认 `Name` | 做不了"掩码后前缀"匹配 |
| **只支持 `exact`**（无 lpm/ternary） | `Parser.scala:432` 抛错 | L3 只能 /32 主机路由 |
| **每张表必须有 `const entries`** | `XlsBackend:611` 抛错 | 空表编译失败 |
| **不能给切片赋值** | `Parser.scala:526` err | 不能改半字节字段 |
| **同一 parser 状态在不同路径偏移必须相同** | `ChiselBackend:1103` 抛错 | 变长封装（可选 VLAN）做不了 |
| 无 header stack / `setValid` / `push_front` / `checksum` / `hash` | — | VLAN 增删、校验和库函数都用不了 |
| 顶层 const、多 key 表、`sel/三元/~`、Register/Counter 均可用 | demo9/demo10 为活样本 | — |

### 两个设计要点（写进 demo 注释与文档 §2）

1. **key 门控代替控制流**：`route_table` 的 key 含 `meta.fwdType`，只有 L2 判为"上三层"
   （`FWD_L3=2`）的包才可能命中路由条目（条目第一段固定 `8w2`），其余落到 `default: nop()`
   直通 ⇒ 等价于条件执行，且完全在 exact 能力内。**不需要在 action 里写 guard 三元。**
2. **字段单一写者**：逐字段规划写者（classify 管 ipLen/dropReason；mac_table 三个 action
   互斥管 fwdType/outPort/outPortIdx；route_table 的 l3_forward 条件覆盖 outPort）。
   `to_l3()` **刻意不写** `outPort`，把出端口留给路由表决定，避免跨表写冲突。

### 报文编辑：RFC 1624 校验和增量更新

`l3_forward` 里**顺序不能反**：先算校验和（此时读到旧 TTL）→ 再递减 TTL → 再改 MAC。
```
hdr.ipv4.hdrChecksum = ~(~HC + ~((bit<16>)ttl) + ((bit<16>)ttl - 16w1));
hdr.ipv4.ttl = hdr.ipv4.ttl - 8w1;
```
手算核对：HC=0x1234、TTL 64→63 ⇒ HC'=0x1236，IR 求值结果一致。

### 新增 `p4xls eval-ir`（`src/main/scala/p4xls/EvalIr.scala`）

`P4C.Interp` 的第一个 CLI 入口：`p4xls eval-ir <fn.ir> --in hdr.ipv4.ttl=64 ... [--json]`。
输入/输出路径口径取自 IR 文件的 `// p4c-params:` / `// p4c-sinks:` 注释，未给的输入自动填 0。
补上了"形式验证只证明自洽、不证明逻辑符合预期"的空缺。

`scripts/demo12_verify.py` 用它做 **30 条断言，全部通过**（校验和的期望值由 Python 里
**独立实现的 RFC 1624 公式**给出，不抄运行结果 —— 两条独立路径同一结论才算验证）。

### 顺带修掉的工具链 bug

`IrText.scala:292` 解析 `literal(value=...)` 走 `intArg`（内部 `.toInt`）⇒ **超 32 位常量必然溢出**。
用 48 位 MAC `0x00deadbeef01`（= 956397711105）时形式验证报
`解析失败 For input string: "956397711105"`。已改为 `bigArg`（BigInt，支持十进制/`0x`/`0b`）。
修前 `未决 1` → 修后 `等价 16 · 不等价 0 · 未决 0`。

### 踩坑

- **`p4flow` 是 fat jar 优先**：改完 Scala 直接跑 `scripts/p4flow` **不会生效**，
  必须先 `sbt -batch cli/assembly`。这次先踩了一次"改了没生效"，重打包后才确认修复。
- 表项实例 dump 只产出**一个** fn（按 action 名），表项参数取的是某一个实例
  （如 `l3_forward` 的下一跳 MAC 是 `NH_MAC_3`）——断言时要知道这点。
